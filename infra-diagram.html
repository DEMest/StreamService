Инфраструктура стримингового сервиса

Как проект устроен сейчас и почему стоит мигрировать на профессиональную CDN-инфраструктуру. Документ для обсуждения с заказчиком.

Состояние · сейчас

Всё на одном сервере разработчика

Все компоненты — приём стрима, база, API, веб, запись архива и раздача зрителям — работают в Docker-контейнерах на одной машине. Это удобно для запуска, но не масштабируется и завязано на одного человека.

Источник

vMix организатора

На площадке стоит ПК с vMix, который собирает 4 камеры в одну композитную 4K-картинку (сетка 2×2) и отправляет её одним SRT-потоком.

Мой сервер · Docker
Ingest + раздача

MediaMTX

Принимает SRT по UDP:8890, нарезает на HLS-сегменты, пишет архив трансляций на диск.

Backend

NestJS API

Авторизация, события, чат WebSocket, управление организациями и ключами.

Frontend

Next.js Web

Публичный каталог, страницы трансляций, админка, дашборд организации.

Хранилище данных

PostgreSQL

Организации, события, записи, чат, заявки с лендинга.

Файлы

Диск сервера

HLS-сегменты в /hls, архив записей в /recordings (fMP4, сегменты по 3 ч).

Входная точка

Nginx + SSL

HTTPS, проксирование /hls, /api, WebSocket.

Зрители

Браузер

Открывают /watch/<slug>. Скрытый <video> декодирует HLS, видимый <canvas> рисует выбранный квадрант (cam1–cam4 или весь multicam).

SRT push UDP:8890 · ~12 Мбит/с
HLS over HTTPS /hls/live/<slug>/index.m3u8
Узкие места
  • Один канал отдачи на всех зрителей. 100 зрителей × 12 Мбит/с = 1,2 Гбит/с с одного сервера — это потолок и для канала, и для CPU.
  • Нет географического распределения. Зрители из других регионов получают задержку и буферизацию.
  • Архив на том же диске, что и боевая нагрузка. Нет бэкапов, диск конечен.
  • Администрирует один человек. Обновления, инциденты, ротация ключей, мониторинг — всё на мне, без оплаты.
  • Бессрочно «временное» решение. Изначально это был стенд для разработки, не продакшен.
Предложение · следующий этап

Профессиональная инфраструктура с CDN

Разделяем ответственность: специализированный CDN отдаёт видео зрителям, S3-хранилище держит архив, маленький VPS обслуживает API и базу. Это правильная архитектура для продакшен-стриминга и она снимает зависимость от моего сервера.

Источник · без изменений

vMix организатора

Та же композитная 4K-картинка, тот же SRT-поток. На стороне организатора ничего не меняется.

Облачный ingest

CDN ingest-точка

Bunny Stream / Cloudflare Stream / Mux принимают SRT или RTMP, сами делают транскод и HLS-раздачу через свою глобальную сеть.

CDN · отдача зрителям

Глобальная сеть точек

Видео раздаётся с ближайшего к зрителю узла. 100 зрителей или 10 000 — нагрузка не на нас.

SRT push
внутри CDN
Маленький VPS · ~$10–20/мес
Backend

NestJS API

Авторизация, события, чат, интеграция с CDN по API.

База

PostgreSQL

Метаданные: организации, события, ссылки на записи в S3.

Архив записей

S3-хранилище

Backblaze B2 / Cloudflare R2 / Selectel. Запись копируется из CDN после окончания трансляции. Дёшево, надёжно, бессрочно.

Frontend

Next.js на Vercel

Веб-приложение деплоится отдельно, бесплатный план покрывает текущую нагрузку. SSL и CDN из коробки.

Зритель

Браузер · live

Открывает страницу трансляции, плеер тянет HLS напрямую с CDN — быстрая отдача, нет буферизации.

Зритель

Браузер · архив

Открывает прошедшую трансляцию, плеер тянет файл из S3 (или через CDN, если включён кеш).

Зритель

Чат + API

WebSocket-чат и REST идут на наш маленький VPS — это малая нагрузка, сервер с ней справится легко.

Зритель

Каталог

Главная страница, страница организации — статика с Vercel, мгновенно.

Что мы получаем
  • Масштабируемость: 1000 зрителей и 10 — одна и та же цена на инфраструктуру для нас, CDN сам разруливает.
  • Стабильность: SLA от CDN-провайдера, дублирование узлов, мониторинг — это их работа, не моя.
  • Архив отделён от боевой нагрузки и не теряется при сбое сервера.
  • Прозрачные расходы: платится по факту просмотров, есть подробная статистика.
  • Независимость от меня как администратора. Любой DevOps сможет подхватить — стандартный стек.

Как будет проходить переезд

План миграции

Шаг 1

Выбор CDN

Тестируем 1–2 провайдера на реальном стриме, сравниваем задержку и качество. Подписываемся на оптимальный.

Шаг 2

Переключение ingest

Меняем настройку SRT в vMix на адрес CDN. Параллельно держим старый сервер как fallback на 1–2 трансляции.

Шаг 3

S3 и архив

Настраиваем выгрузку записей в S3, переписываем страницу архива на ссылки оттуда. Старые записи переносим вручную.

Шаг 4

Вынос API и Web

API+БД едут на чистый VPS, Web — на Vercel. Старый сервер выключается.
