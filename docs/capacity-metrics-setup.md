# Метрики ёмкости: разовая настройка на сервере

Экран `/admin/capacity` показывает, сколько зрителей выдерживает канал. Часть
данных API снимает сам (железо, телеметрия плееров), но **фактическую отдачу
видит только nginx** — кэш специально не пускает запросы сегментов дальше.
Чтобы API мог читать его лог, нужен общий том.

Это делается **один раз**. Дальше всё едет автодеплоем.

## Что уже сделано автоматически

После обычного деплоя (мерж в `main`) на сервере уже есть:

- том `<имя проекта>_nginx_logs`, созданный стеком StreamService;
- контейнер `api`, смонтировавший его в `/var/log/nginx` на чтение;
- обновлённый `infra/deploy/nginx-streamservice.conf` в репозитории.

До шагов ниже метрики отдачи показывают нули. Это не поломка: экран,
телеметрия плееров и блок «Железо сервера» работают, счётчиков nginx просто
ещё нет.

## Шаг 1. Узнать имя тома

```bash
docker volume ls | grep nginx_logs
```

Ожидается что-то вроде `streamservice_nginx_logs`. Если строки нет — стек
StreamService ещё не передеплоен после этих изменений, начните с деплоя.

## Шаг 2. Подключить том к стеку nginx

Стек nginx живёт **вне** репозитория StreamService, поэтому автодеплой его не
трогает. В его `docker-compose.yml` добавить сервису nginx:

```yaml
    volumes:
      - nginx_logs:/var/log/nginx
```

и в конце файла:

```yaml
volumes:
  nginx_logs:
    external: true
    name: streamservice_nginx_logs   # имя из шага 1
```

Обратите внимание: у nginx том **без** `:ro` — он туда пишет.

## Шаг 3. Обновить конфиг nginx

Скопировать актуальный `infra/deploy/nginx-streamservice.conf` из репозитория
в конфиг сервера. В нём появились три вещи:

- `log_format capacity` — формат, который разбирает API;
- `access_log /var/log/nginx/capacity.log capacity;` в обеих HLS-локациях;
- отдельная локация для телеметрии плеера с ограничением частоты.

**Формат лога обязан совпадать** с `CAPACITY_LOG_FORMAT` в
`apps/api/src/capacity/nginx-log.ts`. Разъехавшись, они молча перестанут
понимать друг друга: метрики обнулятся, и ни одной ошибки нигде не появится.

Проверить синтаксис:

```bash
docker exec streamservice-nginx nginx -t
```

## Шаг 4. Пересоздать контейнер nginx

⚠️ **Не во время эфира.** Добавление тома требует именно пересоздания
контейнера — `reload` тут не поможет. Раздача видео прервётся на несколько
секунд. С сегментами по 2 с и окном плейлиста в 80 с зрители обычно не
замечают, но проверьте, что сейчас никто не транслирует:

```bash
curl -s -u "$MEDIAMTX_API_USER:$MEDIAMTX_API_PASS" http://127.0.0.1:9997/v3/paths/list | grep -c '"ready":true'
```

Ноль — можно продолжать. Затем в каталоге стека nginx:

```bash
docker compose up -d --force-recreate nginx
```

## Шаг 5. Проверить, что данные пошли

Лог появился и растёт:

```bash
docker exec streamservice-nginx sh -c 'ls -l /var/log/nginx/capacity.log && tail -3 /var/log/nginx/capacity.log'
```

Строка должна выглядеть так (шесть полей через `|`):

```
2026-08-30T14:03:11+03:00|200|1048576|0.004|HIT|/api/v1/public/orgs/liga/streams/court-a/live/hls/p720/seg17.ts
```

API видит тот же файл:

```bash
docker exec streamservice-api sh -c 'tail -1 /var/log/nginx/capacity.log'
```

После этого откройте `/admin/capacity` при идущем эфире: «Отдача» и «Попадания
в кэш» перестанут быть нулевыми в течение 10–20 секунд.

## Шаг 6. Ротация лога — обязательно

Без ротации `capacity.log` растёт непрерывно: при 200 зрителях это порядка
**2,4 ГБ в сутки** эфира. Том лежит на том же диске, что HLS и записи, а
заполненный диск рвёт эфир — то есть метрика, поставленная следить за
здоровьем сервера, сама станет причиной аварии.

Создайте на сервере `/etc/logrotate.d/streamservice-capacity`:

```
/var/lib/docker/volumes/streamservice_nginx_logs/_data/capacity.log {
    daily
    rotate 3
    size 200M
    missingok
    notifempty
    compress
    copytruncate
}
```

`copytruncate` здесь принципиален: при нём nginx не нужно перезапускать или
слать сигнал, а читатель лога распознаёт усечение файла и продолжает с начала,
ничего не теряя и не задваивая.

Проверить, что правило синтаксически верно и что бы оно сделало:

```bash
sudo logrotate -d /etc/logrotate.d/streamservice-capacity
```

## Необязательное: тревоги в телеграм

Письма уходят через уже настроенный SMTP. Чтобы дублировать их в телеграм,
добавьте в корневой `.env` проекта:

```
TELEGRAM_BOT_TOKEN=...
TELEGRAM_CHAT_ID=...
```

Пусто — уведомления приходят только письмом, ничего не ломается.

## Если канал сервера не 750 Мбит/с

Ширина канала — единственное число во всей подсистеме, которое неоткуда
измерить. От неё считается и заполнение, и потолок по зрителям:

```
UPLINK_MBPS=750
```

Ошибка здесь смещает **все** выводы о необходимости CDN, поэтому цифру стоит
уточнить у хостера, а не брать на глаз.
