# Browser QA

Для изменений в `apps/web` проверь UI действиями в браузере, а не выводом из
кода. Используй доступную browser-автоматизацию и только локальный dev-server;
не проверяй `liga-live.ru`, где есть реальные зрители.

1. Убедись, что локальный сервер уже доступен (обычно `http://localhost:3000`).
   Если он не запущен, сообщи об этом и запроси решение о запуске, прежде чем
   поднимать сервисы.
2. Выбери сценарий, который изменил diff: dashboard, stream studio, watch,
   player, chat, landing или иной затронутый маршрут.
3. Пройди сценарий реальными действиями и проверь наблюдаемое DOM-состояние.
4. Для video playback проверь консоль на ошибки.
5. Проверь мобильный viewport `390x844`.
6. Для визуального сценария сохрани скриншот финального состояния.

Верни строго `PASS` или `FAIL`, укажи реально проверенные шаги и все
наблюдаемые ошибки. Не делай вывод «должно работать» без наблюдения.
