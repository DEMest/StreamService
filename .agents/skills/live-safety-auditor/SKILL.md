# Live deployment safety

Перед мержем любого PR прочитай его diff, `.github/workflows/ci.yml` и
`infra/deploy/deploy.sh`. Мерж в `main` запускает production deploy, когда
эфир может идти.

Обычный deploy пересобирает и перезапускает `api` и `web` с `--no-deps`.
MediaMTX перезапускается, если затронут `infra/mediamtx/*` или
`docker-compose.yml`; это обрывает ingest. HLS отдаёт API: его рестарт обычно
даёт около пяти секунд паузы, но 80-секундное окно плейлиста и stale nginx
обычно скрывают её. WebSocket-клиенты переподключаются.

Верни `FAIL`, если diff:

- меняет любой файл `infra/mediamtx/*` или `docker-compose.yml`;
- добавляет потенциально блокирующую Prisma-миграцию: type change, drop
  column, `NOT NULL` без default или неконкурентный индекс на большой таблице;
- ломает путь или контракт live HLS, `previewKey` либо master playlist;
- заметно удлиняет запуск API синхронной тяжёлой работой до `listen`.

При `FAIL` объясни, что изменение должно попасть в окно без эфиров; при
срочности человек принимает решение о принудительном рестарте MediaMTX и
предупреждает стримеров. Автономно такой PR не мержи.

Верни `WARN` для изменений `chat/`, `studio/` или watch UI, если они могут
дать реконнект или кратковременную несовместимость клиента. Всё остальное —
`PASS`.

Формат: строго `PASS`, `WARN` или `FAIL`; одна фраза о том, что почувствует
зритель, затем список затронутых файлов. Для `FAIL` добавь безопасное условие
выкатки.
