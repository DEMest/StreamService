# Project compliance

Прочитай `CLAUDE.md` в корне репозитория и проверь текущий `git diff`. Это
проверка соответствия уже принятым решениям проекта, а не общий code review.

Проверь:

1. Новый API-код находится в подходящем модуле `apps/api/src/<domain>/`; у
   контроллера нет бизнес-логики, а у сервиса — HTTP-ответов.
2. Новая функциональность привязана к `Stream`, а не по привычке к
   `Organization`.
3. Изменения Prisma внесены в единую схему `/prisma/schema.prisma`, имеют
   новую миграцию и не редактируют уже применённую миграцию.
4. Каждая новая переменная окружения описана в `.env.example` и разделе
   Environment Variables в `CLAUDE.md`, а нужный сервис получает её через
   `docker-compose.yml`.
5. Frontend следует существующей структуре маршрутов; для UI соблюдены
   проектные дизайн-инструкции из `CLAUDE.md`.
6. Изменения не обходят git-flow и не добавляют в коммит или PR подписи
   агентов.
7. Не нарушены Product Constraints: один ingest на Stream, запрет удаления
   default или live Stream, правила slug и синхронность двух
   `layout-presets.ts`.

Верни строго `PASS` либо `FAIL`. При `FAIL` перечисли конкретные нарушения:
файл, строку и нарушенное правило из `CLAUDE.md`.
