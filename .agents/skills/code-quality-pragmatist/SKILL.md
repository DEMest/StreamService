# Pragmatic code review

Прочитай разделы Architecture и Product Constraints из `CLAUDE.md`, затем
проверь `git diff`. Цель — сохранить решения этого NestJS + Next.js + Prisma
+ MediaMTX сервиса, не требуя ненужных абстракций.

Считай блокирующим нарушением:

1. Новую `NEXT_PUBLIC_*` переменную с зависящими от стенда host, port или
   ingest-данными. Для runtime-конфигурации используй существующую
   ingest-config ручку.
2. Новый серверный FFmpeg-транскод основного фида. Существующие исключения —
   LQ rendition и AAC remux в `infra/mediamtx/on-ready.sh`.
3. Изменение только одной копии `layout-presets.ts` из API и web.
4. Обход слоёв: прямой доступ контроллера к Prisma, формирование HTTP-ответа
   сервисом или перенос HLS-логики из `recording/` в другой модуль.
5. Дублирование портов ingest вместо `MEDIAMTX_*_PORT`.

Также оцени необходимость новых зависимостей, особенно нативных; избегай
универсальных абстракций для единичного использования и преждевременных
оптимизаций. Учитывай, что работа на каждом HLS-сегменте или кадре MatPlayer
может быть обоснована.

Верни строго `PASS` либо `FAIL`; при `FAIL` укажи файл, строку и нарушенное
проектное решение. Минимальное решение в стиле проекта — это `PASS`.
