# Страница турнира: эфир, чат и лента схваток

Дата: 7 ноября 2026. Статус: черновик, формулировки уточняются с заказчиком.
Документ серии, детализирующей [`../srs.md`](../srs.md). Описывает, как
зритель смотрит турнир на сайте и в основном приложении: эфир, чат и
ленту схваток, которые снимают медиагенты
([`2026-11-07-media-agent-app.md`](2026-11-07-media-agent-app.md)).
Турнир, каналы и личные страницы — в
[`2026-11-07-app-home-accounts-roles.md`](2026-11-07-app-home-accounts-roles.md).

Страница одинакова на сайте и в приложении; порядок работ — сначала веб
([`../development-principles.md`](../development-principles.md)).

Коды требований: FR-300 и дальше, NFR-80 и дальше.

---

## 1. Термины

| Термин | Значение |
|---|---|
| Страница турнира | Главная страница события: эфир, чат, лента схваток, расписание. Работает до турнира (предстоящий), во время и после |
| Эфир турнира | Каналы турнира (категория `tournament`) в плеере: композит 2×2 или раскладка нескольких каналов, по одному на ковёр |
| Клип схватки | Видео одной схватки, снятое медиагентом, с подписью «кто с кем» |
| Лента схваток | Список клипов турнира под плеером. Пополняется во время турнира, по мере того как медиагенты выкладывают съёмку |

---

## 2. Как выглядит страница

Формат — как страница видео на YouTube: большой плеер сверху, чат сбоку,
под плеером — то, что относится к этому эфиру.

```
 ┌──────────────────────────────────────────┬──────────────┐
 │                                          │              │
 │      ПЛЕЕР: 4 экрана (ковры 1–4)         │     ЧАТ      │
 │      переключение камеры, раскладка      │  (выдвижной, │
 │                                          │  сворачива-  │
 │                                          │   ется)      │
 ├──────────────────────────────────────────┤              │
 │ Название турнира · организатор · даты    │              │
 │ [Подписаться] [Заказать съёмку]          │              │
 ├──────────────────────────────────────────┴──────────────┤
 │ Схватки турнира           [поиск по фамилии] [ковёр ▾]  │
 │ ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐             │
 │ │ превью │ │ превью │ │ превью │ │ превью │  …          │
 │ └────────┘ └────────┘ └────────┘ └────────┘             │
 │ (●)Иванов — Петров(●)  Сидоров — Козлов  …              │
 │ ковёр 2 · 13:05        ковёр 1 · 13:10                  │
 └─────────────────────────────────────────────────────────┘
```

- **Плеер.** Каналы турнира — четыре экрана в раскладке или композит 2×2 с
  выбором камеры: всё, что умеет плеер сегодня (FR-11, FR-12, FR-13).
  Сервер кадр не пересобирает (SRS INV-1).
- **Чат.** Справа от плеера на широком экране, под плеером на телефоне. Его
  можно свернуть и выдвинуть обратно; свёрнутый чат освобождает место
  плееру. Имена в чате — по аккаунтам (FR-180).
- **Под плеером.** Название турнира, организатор, даты, подписка (FR-170),
  заказ съёмки (FR-220, FR-221).
- **Лента схваток.** Клипы турнира, новые сверху. У каждого — превью,
  длительность и мелким текстом пара: «Иванов — Петров · ковёр 2 · 13:05».
  Если у участника есть аккаунт, рядом с фамилией его аватар; нажатие на
  аватар или фамилию открывает его личную страницу (FR-150).
- **Поиск и фильтр.** Поиск по фамилии участника внутри турнира, фильтр по
  ковру. Поиск по сайту (FR-33) тоже находит клипы и ведёт на эту страницу
  с открытым клипом.

На телефоне порядок сверху вниз: плеер, строка с названием и кнопками,
вкладки «Схватки» и «Чат».

## 3. Сценарии

### 3.1 Смотрю эфир и пересматриваю схватку

1. Зритель смотрит эфир турнира.
2. Под плеером появляется клип только что закончившейся схватки.
3. Зритель нажимает на клип — тот начинает играть **мгновенно**, без
   заметной загрузки (§4).
4. Клип открывается в плеере поверх эфира; эфир ставится на паузу и
   продолжает буферизоваться. Кнопка «Вернуться в эфир» возвращает к
   живой картинке.
5. Из клипа можно перейти к следующему свайпом или стрелкой — как в
   вертикальной ленте (FR-42); следующие клипы уже загружены наперёд.

### 3.2 Ищу схватку

1. Зритель вводит фамилию в поиск по турниру — лента оставляет схватки
   этого участника.
2. Или ищет фамилию в общем поиске — получает клипы со всех турниров и
   переходит на страницу турнира с открытым клипом.

### 3.3 Лента обновляется по ходу турнира

- Клип появляется в ленте сразу, как медиагент загрузил его и сервер
  подготовил его к показу (§4.2). Обновление приходит событием по тому же
  WebSocket, что и чат; страницу перезагружать не нужно.
- Подтверждение работы медиагента организатором (FR-243) на публикацию не
  влияет: клип виден сразу, подтверждение нужно только для денег.

### 3.4 До и после турнира

- **До:** вместо эфира — заставка предстоящего турнира с временем начала,
  ниже расписание известных схваток (FR-200) и заказ съёмки.
- **После:** вместо эфира — записи эфиров каналов турнира (FR-15), лента
  схваток остаётся целиком.

## 4. Мгновенный старт клипов

Требование заказчика: клип начинает играть сразу по нажатию, даже на слабом
мобильном интернете, — как лента TikTok, которая загружает несколько видео
наперёд. Решение складывается из четырёх частей.

### 4.1 Что подготавливает сервер

- Медиагент загружает исходник в высоком качестве. Из него сервер делает
  **лесенку копий для доставки** — 1080p/720p/480p/240p в H.264, — как для
  живого эфира. Транскодируются копии, исходник не меняется (SRS INV-1); H.264
  нужен потому, что HEVC с телефона играет не во всех браузерах.
- Клип нарезается на HLS-сегменты с **коротким началом**: первые сегменты
  по 1 с, дальше по 2–4 с. Чтобы начать показ, плееру нужен один короткий
  сегмент нижней ступени — десятки килобайт.
- Для каждого клипа готовятся **постер** (кадр) и **анимированное превью**
  в несколько секунд в самом низком качестве: их видно в ленте до нажатия.
- Сегменты клипа неизменяемы: раздаются через CDN (NFR-3) с долгим
  кэшированием, так что второй зритель получает их уже из кэша CDN.

### 4.2 Публикация

Клип попадает в ленту, когда готовы постер и нижняя ступень. Верхние
ступени дозревают после — первые зрители могут начать с 480p и подняться
выше, когда остальное будет готово.

### 4.3 Предзагрузка в клиенте

- Для клипов, видимых в ленте, и следующих 2–3 по порядку клиент заранее
  загружает плейлист, init-сегмент и **первый сегмент нижней ступени**.
- Объём предзагрузки ограничен бюджетом: на быстрой сети — до нескольких
  клипов вперёд, на медленной — только ближайший, в режиме экономии
  трафика — только постеры. Сеть оценивается по скорости последних
  загрузок; на вебе дополнительно учитываются Network Information API и
  `Save-Data`.
- Предзагрузка не мешает эфиру: она уступает полосу живому плееру и
  отменяется, когда клип ушёл из видимой области.
- Плеер клипов держит готовые декодеры для следующего клипа (на вебе —
  заранее созданный скрытый `<video>`, в приложении — заранее
  подготовленный экземпляр плеера), чтобы переход был без пустого кадра.

### 4.4 Старт воспроизведения

- По нажатию клип стартует с той ступени, первый сегмент которой уже в
  памяти, и поднимает качество, как обычно.
- Постер показывается мгновенно, пока декодируется первый кадр.

## 5. Требования

### 5.1 Страница

| Код | Требование |
|---|---|
| FR-300 | Страница турнира — плеер каналов турнира сверху (раскладка или композит с выбором камеры), чат сбоку на широком экране и под плеером на телефоне, под плеером — название, организатор, даты, подписка и заказ съёмки, ниже — лента схваток |
| FR-301 | Чат сворачивается и выдвигается обратно; свёрнутый чат отдаёт место плееру; состояние запоминается у зрителя |
| FR-302 | До турнира вместо эфира — заставка со временем начала и расписание известных схваток; после турнира — записи эфиров и полная лента схваток |
| FR-303 | Страница одинакова на сайте и в основном приложении |

### 5.2 Лента схваток

| Код | Требование |
|---|---|
| FR-310 | Лента — клипы схваток турнира, новые сверху: постер, длительность, мелким текстом пара, ковёр и время |
| FR-311 | У участника с аккаунтом рядом с фамилией аватар; нажатие на аватар или фамилию открывает его личную страницу |
| FR-312 | Клип появляется в ленте во время турнира без перезагрузки страницы, событием по WebSocket |
| FR-313 | Клип открывается поверх эфира; эфир на паузе и продолжает буферизоваться; «Вернуться в эфир» возвращает к живой картинке |
| FR-314 | Переход к следующему клипу свайпом или стрелкой, как в вертикальной ленте (FR-42) |
| FR-315 | Поиск по фамилии участника внутри турнира и фильтр по ковру; общий поиск (FR-33) находит клипы и открывает страницу турнира с клипом |
| FR-316 | Клип публикуется сразу после подготовки; подтверждение работы медиагента организатором на публикацию не влияет |

### 5.3 Скорость клипов

| Код | Требование |
|---|---|
| NFR-80 | Клип, первый сегмент которого предзагружен, начинает играть по нажатию не позже чем через 0,5 с. Не предзагруженный — не позже чем через 2 с на мобильной сети 4G и 3 с на сети около 1,5 Мбит/с. Цифры проверяются телеметрией плеера (NFR-20) |
| NFR-81 | Для клипа сервер делает лесенку копий 1080p/720p/480p/240p в H.264; исходник медиагента не меняется (SRS INV-1) |
| NFR-82 | Первые сегменты клипа — по 1 с, следующие — 2–4 с; постер и короткое превью в низком качестве готовятся вместе с нижней ступенью |
| NFR-83 | Клип попадает в ленту, когда готовы постер и нижняя ступень; верхние ступени дозревают после. Время от конца загрузки до появления в ленте — не больше 1 мин |
| NFR-84 | Сегменты, плейлисты и постеры клипов неизменяемы и раздаются через CDN (NFR-3) с долгим кэшированием |
| NFR-85 | Клиент предзагружает плейлист, init-сегмент и первый сегмент нижней ступени для видимых клипов и следующих 2–3; объём ограничен бюджетом по скорости сети; в режиме экономии трафика — только постеры |
| NFR-86 | Предзагрузка уступает полосу живому эфиру и отменяется, когда клип уходит из видимой области |
| NFR-87 | Подготовка клипов не отнимает ресурсы у живых эфиров: транскод клипов идёт в отдельной очереди обработки записей (SRS NFR-40) с ограничением одновременных задач |

## 6. Модель данных

| Таблица | Содержание | Зачем так |
|---|---|---|
| `Clip` | **Новая**: `id`, `eventId`, `boutId`, `boutShootId`, `agentAccountId`, `status` (`processing` \| `published` \| `failed` \| `removed`), `duration`, `posterPath`, `previewPath`, `manifestPath`, `renditions Json`, `publishedAt`, `createdAt` | Опубликованный клип схватки. S3-ключи по той же схеме, что у архива; `renditions` показывает, какие ступени уже готовы |
| `Bout` | без изменений (спека медиагента) | Пара, ковёр и время для подписи берутся из схватки, а аватары — из аккаунтов участников через `Registration` |

Индексы: `Clip(eventId, publishedAt)` для ленты, поиск по фамилии — через
`AccountRole.searchName` и имена в `Bout`.

## 7. Интерфейсы API (эскиз)

| Маршрут | Назначение | Кто |
|---|---|---|
| `GET /v1/public/events/:id` | Страница турнира: каналы, статус, расписание | без авторизации |
| `GET /v1/public/events/:id/clips?q=&venue=&cursor=` | Лента схваток: постер, превью, пара, аватары, адрес медиа | без авторизации |
| `GET /v1/public/clips/:id/hls/*` | Плейлисты и сегменты клипа; тяжёлые байты — редиректом на CDN | без авторизации |
| WebSocket `/chat`, событие `clip_published` | Новый клип в ленте турнира | все в комнате турнира |

Адреса медиа клипов выдаёт сервер, клиент их не строит (SRS NFR-52).

## 8. Открытые вопросы

| Вопрос | Кто решает | Что зависит |
|---|---|---|
| Виден ли клип всем или только заказчику; нужен ли заказ, чтобы схватка попала в ленту | Заказчик | FR-310, FR-316 |
| Может ли организатор снять клип из ленты, и что тогда с деньгами медиагента | Заказчик | FR-316 |
| Какие эфиры турнира идут в четыре экрана, если каналов больше четырёх | Заказчик | FR-300 |
| Если схватку сняли с двух сторон — показывать оба ракурса (сейчас один медиагент на схватку) | Заказчик | FR-310 |
